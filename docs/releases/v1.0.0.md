# v1.0.0

First stable release. The checks can now be called as a regular step-level action, `uses: diegocrew/action-devops@v1.0.0`, alongside the existing reusable workflow. Both entry points take the same inputs, run the same checks and scripts, and share the same modes and summary.

## New features

- **Action entry point** (`action.yml`): a composite action that runs every enabled check as a step in the calling job. It checks out the calling repository itself (`checkout: false` skips this), accepts `github-security-token` and `renovate-token` as inputs, and supports `audit`, `restrict`, and `advanced` modes: each check tolerates failure, and the final summary step fails the job only in `restrict` mode or on invalid configuration.
- **Self-test**: this repository's CI runs the action next to the reusable workflow.

## Changed

- `README.md` documents both entry points, the action first, and when to choose each.
- The CodeQL language check also reports whether the listed languages need `autobuild`, no build, or a mix.
- The Renovate image is updated to 44.182.2 and `renovatebot/github-action` to v46.3.10.
- From this release, versions follow stable Semantic Versioning: breaking input or behavior changes need a new major version.

## Known limitations

- The action runs checks one after another in one job, so a full run takes longer than the reusable workflow, and all checks share the job's permissions and tools. Use the reusable workflow for parallel runs and per-check isolation.
- In the action, one call cannot mix compiled (`c-cpp`, `go`, `java-kotlin`, `csharp`) and interpreted (`javascript-typescript`, `python`, `ruby`) CodeQL languages; use two steps or the reusable workflow.
- github.com and GitHub-hosted Ubuntu runners only, as before.

## Upgrading

Reusable-workflow callers need no input changes; update the reference to `@v1.0.0`. To switch to the action, move the call from job level to a step:

```yaml
jobs:
  checks:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - uses: diegocrew/action-devops@v1.0.0
        with:
          mode: audit
```

Pass `secrets:` values as `with:` inputs instead.
